## 不同点与我们的选择

### 1. 客户端描述处理（对方零触碰，我们曾做短语黑名单）

对方 v1.4.8 的 `renameAndCompleteTools` 对客户端描述**零改写**：
只改名字，描述逐字出站（`toolshape.go` 内无任何 `Description` 写回，唯一
的描述改写针对他们自己追加的官方 shell/bash 主机替换）。

我们此前有 `bannedDescriptionFragrases`（把 `UTF-8 text file`、
`line-numbered content`、`session skill catalog` 等短语替换成中性措辞），
依据是"真实描述 429 / 假描述 200"的观察。

**我们的 A/B 结论（2026-11-17，同出口 104.28.196.79）**：

```
A = 真实 DSH 描述（含封禁短语原文）  → 429
B = 同样工具、中性描述                → 429
A 再次                                → 429
```

A 与 B 同为 429。但**这个样本是无效的**：该出口当时额度已耗尽（此前同一出口
也跑出过 200），两次请求都落在耗尽窗口内，无法区分变量。

**生产 A/B（同一节点、同一请求、只改脱敏开关）——这才是有效样本**：

| 版本 | 脱敏 | real-multi-stream（真实描述 + 流式） | 45multi / turn3（占位描述、非流） |
|---|---|---|---|
| v0.9.34 / v0.9.35 | 开启 | **200** | 200 |
| v0.9.36 | 关闭 | **429**（双节点一致） | 200 |
| v0.9.37 | 恢复开启 | **200** | 200 |

同一出口、同一请求、几分钟内，唯一变量是脱敏开关 → **描述脱敏是承重的**。

处置：短语黑名单保持**默认开启**（v0.9.37 恢复）；`ZEN_DESC_VERBATIM=1`
仅作对照实验开关。对应回归测试 `toolshape_desc_default_test.go`
（锁定默认开启 + 真实 DSH 描述必须被脱敏）。

> 与对方 v1.4.8 的差异仍在：他们对客户端描述零触碰且线上跑通。说明在我们的
> 组合下（mcp_ 名 + 官方 95KB 提示词 + 本仓库其余整形）描述仍被指纹；他们
> 能过可能源于其他变量（如工具集内容、UA 版本、提示词版本）。我们按实测走：
> 脱敏开启是当前唯一被生产 A/B 证明有效的形态。

### 2. 官方 system prompt 正文（我们 95KB，对方 8.5KB）

- 对方 v1.4.8：`opencode_prompt_v2.txt` = 8535 字节，开头
  `You are opencode, an interactive CLI tool...`
- 我们 v0.9.27 起：`tools/opencode_prompt_v2.txt` = 102501 字节，开头
  `You are an AI agent running in OpenCode, a coding agent harness...`
  （2026-11-16 从官方 CLI 2.2.5 抓包逐字提取，含 219 个 skills 与 `<env>` 块）

**同出口 A/B 实测两者都通过**：

```
同一出口 104.28.201.162、同一 45 工具请求：
  promptA（我们 95KB）= 200
  promptB（对方 8.5KB）= 200
```

两者等价。保留 95KB 版本的理由：它逐字等于当前官方 CLI 的真实输出，与上游
的期望形态完全一致；CLI 升级时我们能重新抓包刷新，而 8.5KB 旧版与现行 CLI
已经脱节。为便于对照，新增 `ZEN_PROMPT_FILE` 可临时替换注入的提示词正文。

（注：这次 A/B 与上面的描述 A/B 不同——描述 A/B 是在耗尽出口上做的，样本
无效；提示词 A/B 出口健康，两者都 200，只能说明"95KB 不劣于 8.5KB"，
不能证明两者等价——要区分需在健康出口上做同样对照。）

## 核心结论（修正后）

**结论一：工具名形态是硬变量。**
官方名（read/edit/...）与客户端原名（pwsh/team_task_*）都不能直接出站；
必须改名成不透明名（mcp_ 前缀），或压缩进官方通道（我们的通道模式）。
有效样本：同出口同请求，官方名 → 429，mcp_ 名 → 200。

**结论二：描述脱敏是承重的。**
同节点同请求只改脱敏开关：开启 200 / 关闭 429（real-multi-stream）。
此前"描述无关"的判断来自无效样本（出口耗尽期）。

**结论三：出口 IP 的额度状态是独立的强变量。**
同一份请求在健康出口 200、在耗尽出口 429，且随时间自行恢复；这解释了
"同一测试时好时坏"。任何 A/B 结论都必须确认出口当时健康。

**因此请求整形需要对齐的点是三样**：工具名形态（mcp_ 前缀）、描述脱敏、
官方 system prompt。其余改动对 429 无影响。
